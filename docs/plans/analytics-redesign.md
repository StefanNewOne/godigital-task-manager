# План: Редизајн на Аналитика (B2)

Статус: **ПРЕДЛОГ — чека одобрување.**

## Барања (сопственик)

1. Избор на **КЛИЕНТ** + **ПЕРИОД** (моментално е tenant-wide, само тековен месец).
2. Метриките поделени по извор: **Instagram**, **Facebook**, **Ад Акаунт (платено)**.
3. По парче содржина: слика vs видео — каков резултат донело.
4. Кампањи со иста структура како во Ад Акаунт: **кампања → публика (adset) → ад**, кој каков резултат.
5. Сѐ поделено по **период** (кој месец кои резултати).

## Изводливост (потврдено во живо)

- Ад insights по `level=campaign|adset|ad` + `time_increment=monthly` → хиерархија + месечна разбивка директно од Meta. ✅
- IG постови со media_type (image/video/reel/carousel) + reach/engagement/views. ✅ (веќе снимено)
- **Ограничување:** FB **органски по-пост reach/impressions се укинати** од Meta (v21). FB органски = само page-ниво (followers, ангажман, page views, video views). Нема FB per-post reach.

## Дизајн

- Нов endpoint `GET /analytics/client/:id?from=YYYY-MM&to=YYYY-MM` враќа:
  - `instagram`: постови групирани по media_type + по месец; тотали.
  - `facebook`: page-ниво метрики по месец (PageSnapshot временска серија).
  - `ads`: хиерархија кампања→adset→ад со spend/reach/impressions/ctr, по месец.
- **Ад дата**: се влече **во живо од Meta** при отворање (со `level` + `time_increment=monthly`) — секогаш свежо, без огромно складирање на adset/ад×месец. (Алтернатива: складирање преку cron.)
- IG/FB: од складирани `MetricSnapshot`/`PageSnapshot` (cron на 6ч + рачно копче).
- Web: клиент+период селектор горе; табови/секции **Instagram · Facebook · Реклами**; во Реклами — collapsible кампања→adset→ад; месечна разбивка.

## Отворени прашања

1. Длабочина на ад-хиерархија: само кампања / кампања+adset / целосно кампања→adset→ад.
2. Ад дата: во живо при отворање (секогаш свежо) наспроти складирано (на 6ч + копче).

## Ажурирање на метрики (одговор на прашање)

- Автоматски cron `metrics.pull`: **на секои 6 часа** (`0 */6 * * *`).
- Рачно: копче „Повлечи метрики" (Админ) — веднаш.
