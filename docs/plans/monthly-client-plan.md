# План: Месечен план на клиенти (одобрување од Директор) + Глобален календар

Статус: **ПРЕДЛОГ — чека одобрување** (§22). Не е имплементирано.

## Мотивација (барање на сопственикот)

Директорот секој месец, до **15-ти**, одобрува **кои клиенти се работат наредниот месец**.

- Потсетник-таск на 15-ти; ако задоцни (по 15-ти) → **АЛАРМ** додека не потврди.
- Клиент што **не е одобрен** за месец M → **не може** да му се создаде капа ниту интервентен таск за M.
- Ако ниеден клиент не е одобрен за M → нема креирање за M воопшто.

Ова го заменува „глобален статус на клиент" со **месечно одобрување по клиент**.

---

## Дел 1 — Месечен план (модел + порта + UI + cron)

### 1.1 Податочен модел (Prisma миграција)

```prisma
model MonthlyPlan {                 // потврда на листата за еден месец
  id            String   @id @default(uuid(7)) @db.Uuid
  tenantId      String   @default("godigital")
  monthKey      String                        // „2026-11"
  confirmedById String?  @db.Uuid             // Директор што ја потврди
  confirmedAt   DateTime?
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  clients       MonthlyPlanClient[]
  @@unique([tenantId, monthKey])
}

model MonthlyPlanClient {           // еден ред по клиент во планот
  id           String  @id @default(uuid(7)) @db.Uuid
  tenantId     String  @default("godigital")
  monthlyPlanId String @db.Uuid
  plan         MonthlyPlan @relation(fields: [monthlyPlanId], references: [id])
  clientId     String  @db.Uuid
  active       Boolean @default(true)
  @@unique([monthlyPlanId, clientId])
}
```

- „Одобрен за M" = постои `MonthlyPlan` за M со `confirmedAt != null` **и** `MonthlyPlanClient(active=true)` за клиентот.
- Append-friendly: потврдата се менува само преку сервис (EventLog запис).

### 1.2 Порта (гејт) на креирање

- `confirmMonth(clientId, month)` и `createExtraTask(...)`: пред создавање проверка
  `isClientApprovedForMonth(clientId, month)`. Ако не → `AppError('MONTH_NOT_APPROVED', 'Клиентот не е одобрен за {месец}. Директорот мора да ја потврди месечната листа.', 400)`.
- Cron `slots.generate` (20-ти): генерира **само** за одобрени клиенти за наредниот месец.
- Нова функција во `packages/core` (чиста): `monthApprovalRequired(monthKey)` + помош за пораки; гејтот во API го користи.

### 1.3 Director UI — „Месечен план"

- Нов екран/модал (во **Клиенти**, копче „Месечен план") видлив само за `dir`.
- Покажува наредниот месец, листа клиенти со toggle (Активен/Неактивен), состојба „Потврдено / Чека потврда", копче **„Потврди месец"**.
- Default: сите активни од претходниот потврден месец (или сите клиенти првиот пат).
- Ендпоинти: `GET /monthly-plan/:month`, `PUT /monthly-plan/:month` (toggle-и), `POST /monthly-plan/:month/confirm` (само dir).

### 1.4 Потсетник + аларм (worker cron)

- **15-ти 06:00 (Europe/Skopje):** ако нема потврден план за M+1 → `Notification(potsetnik)` до сите активни `dir` „Потврди ги клиентите за {M+1}".
- **16-ти … крај на месец, дневно:** ако сè уште нема потврда за M+1 → `Notification(kritichen)` до Директор(ите) (модал „Видено", §16).
- Идемпотентно преку `dedupeKey = monthly-plan:{monthKey}:{level}`.

### 1.5 „Генерирај следен месец" (копче)

- Во Клиенти/Календар, копче (само dir/am) што повикува генерирање предлог-распоред за **сите одобрени** клиенти за M+1 (рачна верзија на cron-от). Паѓа со порака ако планот не е потврден.

### 1.6 Тестови

- core: `isClientApprovedForMonth` табеларно.
- api integration: гејт (неодобрен → 400; одобрен → 201/200), confirm-flow, cron reminder/alarm идемпотентност.
- web: Месечен план модал (toggle + потврди), гејт-порака.

### 1.7 Rollback

- Backwards-compatible миграција (нови табели, без промена на постоечки). Гејтот зад feature-проверка: ако нема ниту еден `MonthlyPlan` во системот, гејтот е „off" (не крши постоечки демо-тек) додека не се потврди првиот месец. → **одлука за потврда:** дали гејтот да е активен веднаш или мек до првата потврда.

## Дел 2 — Глобален календар „Сите клиенти" (независно)

- Во **Календар**: dropdown добива опција **„Сите клиенти"** (default).
- Нов ендпоинт `GET /calendar/slots?month=YYYY-MM` (сите клиенти, tenant-scoped) или прошири `/slots` да прифати без `clientId`.
- Секое поле од календарот прикажува **кругчиња/точки по клиент** (боја на клиент) за тасковите тој ден; при многу — „+N".
- Клик на ден → страничен панел со **сите таскови за тој ден** (сите клиенти), со име на клиент + статус.
- Пренасочување во таск/капа при клик на ставка.
- Per-client приказ останува (кога ќе се избере клиент).
- Тестови: web компонент (сите-клиенти агрегат + ден-панел), api за новиот ендпоинт.
