# План: Календар + животен циклус на клиент (редизајн)

Статус: **ПРЕДЛОГ — чека одобрување** (§22). Не е имплементирано.
Заменува дел од `monthly-client-plan.md` (Директор-одобрува-клиенти → Директор-гаси-клиент + АМ-календари).

## Модел (потврден со сопственикот)

### 1. Акаунт менаџер — календари (без одобрување од Директор)

- **Стандарден календар** (еден): кои денови се видео/графика — важи за сите клиенти со стандарден план.
- **Посебен календар по клиент**: се сетира одделно, еден по еден (override на стандардниот).
- **Аларм на 15-ти** (месечно): АМ да го потврди/генерира наредниот месец. Ако не → ескалирачки аларм (како кај monthly-plan).
- Генерирањето на слотови/деца за наредниот месец е дело на АМ (потврда на месец).

### 2. Директор — гаси клиент (cutoff по крај на месец)

- Директор деактивира клиент (пр. 20.09).
- Од тој момент: тасковите/датумите за тој клиент може да се активираат/закажат **само до крај на тековниот месец** (30.09).
- Датуми во **нареден** месец (и понатаму) се блокирани — дури и ако АМ имал сетирано календар за 3 месеци напред.
- Треба: `Client.deactivatedAt` (timestamp) + помош `clientActiveForDate(client, date)` = `!deactivatedAt || date <= крајНаМесец(deactivatedAt)`.

### 3. Гејт на активација/затворање

- Активацијата на таск го користи датумот од **мртвиот слот** (останува ист, D-2).
- Не може да се активира/затвори таск ако:
  - датумот е во месец **без потврден календар** за тој клиент, ИЛИ
  - клиентот е **изгасен** и датумот паѓа по cutoff-от (нареден месец).
- Порта во: `confirmMonth`, активација на деца (капа), `createExtraTask`, промена на датум (не смее да носи во непокриен/деактивиран период).

### 4. Замрзнување + аларм

- Ако Режисер/Монтажер/Гр. креатор имаат работа што паѓа во непокриен период (нема календар / клиент изгасен):
  - тасковите **замрзнуваат** (не се преодуваат понатаму),
  - **аларм** до Акаунт менаџер (да сетира календар) — ниво `alarm`/`kritichen`.
- Rez/krea не може да резервира датуми освен до крај на тековниот месец во тие услови.

### 5. Режисер — „Создај капа" (нормална)

- Копче за Режисер → создава **нормална видео капа** (podgotovka → scenarija → scenKajKlient → snimanje → zatvoren), рачно, **независно од календарот**.
- Различно од „интервентно видео" (кое прескокнува претпродукција и стартува во chekaRezija).

## Влијание врз постоечкото

- `monthly-client-plan.md` (Директор одобрува клиенти + мек гејт) се **преобликува**:
  - „одобрување на клиенти" → **деактивација на клиент** (Директор) со cutoff.
  - месечната потврда → **АМ сетира календар/генерира месец** (наместо Директор).
- Постоечкиот `MonthlyPlan` модел веројатно се заменува со: `Client.deactivatedAt` + „стандарден календар" концепт + потврда на календар по (клиент, месец).

## Отворени прашања пред имплементација

1. „Стандарден календар" — нов ентитет (default `CalendarConfig` за tenant) со per-client override? Или поле на клиент „користи стандарден / посебен"?
2. „Потврден календар за месец" — по (клиент, месец) статус (како monthly-plan потврда), или изведено од постоење слотови?
3. „Замрзнување" — нов таск-статус/флаг, или само блокирање на преоди + аларм (без нов статус)?
4. Дали „Месечниот план" (MonthlyPlan модел/UI) целосно се вади, или се адаптира?

## Редослед на градење (по одобрување, §22)

core (clientActiveForDate, calendar-gate чисти функции) → Prisma (Client.deactivatedAt, стандарден календар, потврда) → API гејт во активација/датум/затворање + аларми → worker cron (15-ти АМ аларм, замрзнување) → web (АМ календар UI, Директор гаси-клиент, Режисер „Создај капа").
