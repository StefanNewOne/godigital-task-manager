## 3. Backend — што треба (ново, голем дел)

CRM е **нов модул** со сопствена state machine, ентитети и екрани (споредливо со градењето на Task/Capa системот).

### 3.1 Улоги и дозволи (`packages/core`)

- Нова улога **`sales`**: `nav:['crm']`, `start:'crm'`, scope = само свои лидови, **без пристап до Модул 1**.
- Директор: `nav` + `'crm'`; работни CRM статуси „Одобрување понуда" + „Одобрување договор". (Модул-1 дозволите непроменети.)
- Нов екран `'crm'` во `SCREENS` + guard.

### 3.2 Ентитети (Prisma миграција, сите `tenantId`)

`Lead`, `Offer[]`/`Contract[]` (верзии `{v, file, ret?, clientRet?}` — како `Revision`), `Meeting`, `Package`, `ContentPlan` (`{monthKey:{day:'v'|'g'}}`), `LossReason` (enum), `Team`/стандарден тим. Append-only каде треба (верзии, лог).

### 3.3 CRM state machine како ПОДАТОК (`packages/core`, §И2)

- `CRM_FLOW`: 11 чекори + 2 терминални (`novLid→analiza→ponudaIzr→ponudaOdob→ponudaKlient→sostanok→dogIzr→dogOdob→dogKlient→strategija→aktivacija`; `aktiviran`, `izguben`).
- Секој ред `{from, to, actor, guards[], effects[]}` + `transitionLead(...)` (една трансакција: guards → статус → effects → лог), исто како `transitionTask`/`transitionTaskGroup`.
- **Guards:** контакт/извор/пакет (1), документ-анализа (2), нова верзија понуда (3), директор одобри/врати+коментар→3 v+1 (4), прифати/измени/изгубен (5), состанок датум+час+исход (6), пакет+верзија договор (7), одобрување договор (8), потпишан скен/измени/изгубен (9), стратегија+планер пополнет (10), активирај (11). Изгубен само од 5 и 9; „Друго" → белешка задолжителна.
- **Effects:** version bump, `E_ACTIVATE` (види 3.4), assign team, revision/comment.
- Табеларни тестови (како `transitions.fixture.json`).

### 3.4 Активација (чекор 11) — врска со Модул 1

- Креира **Client** во Модул 1 со параметрите на пакетот (видеа/графики/Meta/старт/должина/тип календар) 1:1.
- **Content планер → мртви слотови**: датумите од првиот месец → `PublishingSlot status:'mrtov'`; следните месеци се генерираат на 20-ти (постоечки cron).
- **Стандарден тим**: АМ секогаш · Режисер ако видеа>0 · Гр. креатор ако графики>0 · Аналитичар ако Meta Ads. Само Директор го менува во чекор 11.

### 3.5 Content планер (чекор 10)

- `ContentPlan` per (лид, месец): клик празно→видео→графика→празно; лимит = бројки од договорот; 3 месеци (`CRM_PLAN_MONTHS=3`). Fable фајл = референца.

### 3.6 Видливост, застареност, документи

- Агент: само свои лидови (нов лид на себе). Директор: сите + филтер по агент + таб „Чека мое одобрување".
- Лид без промена **5+ дена** (`CRM_STALE_DAYS=5`) → ознака на картичка + филтер.
- Понуда/договор: интерни верзии; клиент ја гледа само финалната; агент праќа рачно (нема авто-мејл).

### 3.7 API (нови рути)

`GET/POST /leads`, `POST /leads/:id/transition`, качување верзии понуда/договор (presigned R2), `POST /leads/:id/meeting`, `PUT /leads/:id/content-plan`, `POST /leads/:id/activate`. Zod + серверски дозволи.
