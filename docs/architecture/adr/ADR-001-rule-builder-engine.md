# ADR-001 — Rule Builder: bounded, data-driven аларм engine (отповикува D-13)

- **Статус:** Прифатено (одлука на сопственикот, 2026-10-01) — отповикува D-13.
- **Контекст фаза:** B1 (Аларми + Автоматизации).

## Контекст

D-13 (backlog §5b, 2026-09-24) одлучи да **НЕ** се гради генерички rule engine; системските правила останаа тенок on/off toggle над хардкодирани евалуатори (пр. `evaluateCoverageAlarms`). Причина тогаш: генерички engine што извршува произволен `trigger/conditions/actions` JSON би го **дуплирал state machine-от** (спротивно на §3 „derive, not duplicate") и беше преголем за една агенција.

Сопственикот сега бара Rule Builder (2026-10-01) — Директор да создава/уредува аларм-правила без код.

## Одлука

Градиме **ограничен (bounded), типизиран, data-driven** engine — **НЕ** произволен/Turing-complete:

1. **Регистар на типови тригери** — фиксен, кодиран сет евалуатори (пр. `coverage_below`, `status_age_exceeds`, `deadline_approaching`, `client_return_nth`, `scenarios_exceed_slots`, `storage_quota`, `meta_token_expired`). Секој тип има типизиран евалуатор во `packages/core`/API.
2. **`AutomationRule.trigger/conditions/actions`** носат **валидирани параметри** (Zod дискриминирана унија по тип), не код. Пример: `{ trigger: { type: 'coverage_below' }, conditions: { days: 7, scope: 'global' }, actions: { level: 'kritichen', recipients: 'directors' } }`.
3. **Евалуаторите само ЧИТААТ состојба и креираат `Notification`/аларм** — **никогаш не менуваат статус** (нема повик до `transitionTask`/`transitionTaskGroup`). State machine останува единствен извор за преоди → директно ја адресира главната грижа на D-13 (нема дуплирање).
4. **Rule Builder UI** (Админ → Аларми) — CRUD над правила во рамки на познатите типови (dropdown тип → типизирани полиња за услови → акција: ниво + приматели + опсег). Само Директор.
5. Системските правила (денес гатирани по име + `enabled`) се мигрираат во data-driven параметри; `enabled` toggle останува.

## Последици

- **Позитивно:** нов аларм = нов тип-евалуатор (код) + опција во UI; праговите/опсегот/приматели се конфигурираат од Директор без деплој; `AutomationRun` дава аудит.
- **Ограничувања (наменски):** не може да се создаде правило што прави преод/мутира домен — само известувања. Тоа е инваријанта (review + напомена во кодот); штити од дуплирање на §3.
- **Backward-compatible:** постоечкиот `enabled` toggle и системските правила продолжуваат; евалуаторите се рефакторираат да читаат параметри наместо хардкодирани константи.
- **Оценка на ризик:** среден (опсег). Митигација: фазна испорака, типизирана валидација, евалуатори read-only+notify-only.

## Отфрлени алтернативи

- **Задржи D-13** — сопственикот експлицитно бара Rule Builder.
- **Целосно произволен engine** (условна логика/изрази како код) — отфрлен: сложеност + ризик од дуплирање на state machine (оригиналната грижа на D-13).
